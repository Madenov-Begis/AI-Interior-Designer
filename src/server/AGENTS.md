# Инструкции для backend

Эти правила уточняют корневой `AGENTS.md` для `src/server` и серверных Route Handlers.

## Границы

- Route Handler выполняет auth, разбор запроса, validation, вызов сервиса и сериализацию ответа.
- Бизнес-правила и транзакции размещай в `src/server/features`.
- Доступ к бизнес-таблицам выполняй только через Prisma.
- Не импортируй React или клиентские runtime-модули.
- Проверяй ownership, `Profile.status` и роль на сервере.
- Используй единый error envelope и сохраняй `requestId`.
- Не возвращай stack trace, credentials, внутренний prompt или лишние персональные данные.

## Надёжность

- Финансовые изменения выполняй транзакционно и идемпотентно.
- Любая дорогая операция должна уважать rate limit и системные ограничения.
- Не меняй terminal state назад на активный.
- При частичной ошибке Storage очищай загруженные файлы или ставь их в очередь повторного удаления.
- При неизвестном результате транзакции не выполняй компенсирующее действие без подтверждения состояния БД.

## Изменение API или данных

Перед изменением прочитай соответствующие разделы:

- `docs/full-product-documentation.md`;
- `docs/architecture.md`;
- `prisma/schema.prisma`;
- соседние schemas, operations и tests.

При изменении контракта синхронно обнови frontend DTO/клиент, тесты и документацию. Для изменения Prisma создай миграцию; не редактируй уже применённую migration ради нового поведения.

## Проверка

- Запускай релевантные server tests.
- Для Prisma: `pnpm prisma:validate` и при необходимости отдельную test database.
- Для auth, credits, payments и generations проверяй негативные сценарии, повтор запроса и конкурентный доступ.
- Для изменения Route Handler добавляй `pnpm typecheck`, `pnpm lint` и при значимом изменении `pnpm build`.
