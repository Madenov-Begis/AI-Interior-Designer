# Ruvie — синхронизация environment variables

- Дата: 29 августа 2026 года
- Проекты Vercel: `ai-interior-designer`, `ruvie-admin`
- Scope: `Production`
- Значения секретов в отчёт не включены

## Результат

Канонический набор основного приложения содержит 29 прикладных переменных. Наборы в `.env.example`, `.env.local` и Vercel Production синхронизированы со следующими штатными исключениями:

- `NODE_ENV` локально задаёт режим разработки, а в Vercel устанавливается платформой;
- `VERCEL_OIDC_TOKEN` является временной служебной переменной Vercel и не входит в прикладную схему;
- `.env.example` содержит безопасные примеры вместо реальных секретных значений.

Итоговая автоматическая сверка:

- отсутствующие локальные ключи: 0;
- лишние локальные прикладные ключи: 0;
- отсутствующие Production-ключи: 0;
- лишние Production-прикладные ключи: 0;
- расхождения доступных Config-значений: 0;
- обязательные Secret-значения присутствуют: да;
- `admin/.env.example`, `admin/.env.local` и Vercel Production совпадают по ключу и Config-значению: да.

## Явно добавленные значения

- `NEXT_PUBLIC_APP_NAME=Ruvie`;
- `PAYMENT_PROVIDER=disabled`;
- `VERTEX_IMAGE_VALIDATION_MODEL=gemini-2.5-flash`.

Локальная авторизация Google Cloud переведена с файлового `GOOGLE_APPLICATION_CREDENTIALS` на тот же `GOOGLE_APPLICATION_CREDENTIALS_JSON`, который используется в Vercel.

`ADMIN_ACCESS_CODE` и `ADMIN_TOKEN_SECRET` были безопасно сгенерированы заново и синхронно установлены локально и в Vercel. Старые admin-сессии после redeploy недействительны; новый access code хранится только в игнорируемом Git файле `.env.local`.

## Классификация Vercel

Как `Secret` сохранены только чувствительные значения:

- `ADMIN_ACCESS_CODE`;
- `ADMIN_TOKEN_SECRET`;
- `DATABASE_URL`;
- `DIRECT_URL`;
- `GOOGLE_APPLICATION_CREDENTIALS_JSON`;
- `SUPABASE_SERVICE_ROLE_KEY`.

Домены, public Supabase config, названия, модели, лимиты и feature modes сохранены как `Config`. В admin-проекте `VITE_API_BASE_URL` также сохранён как `Config`.

## Не входят в текущую схему

`SENTRY_DSN` и `TRIGGER_SECRET_KEY` остаются будущими интеграциями и не добавлялись как пустые фиктивные переменные. Preview/Development environments Vercel всё ещё требуют отдельного staging-набора и не должны автоматически получать Production-секреты.
