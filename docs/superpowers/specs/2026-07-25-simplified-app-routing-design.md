# AI Interior Designer — упрощённый вход в редактор

## 1. Цель

Убрать промежуточный dashboard и отдельный экран загрузки фотографии. После
Google OAuth пользователь должен сразу попадать в единый редактор, где загрузка
исходного фото является начальным состоянием холста.

Основной пользовательский поток:

```text
Вход → /app → /app/[id] → загрузка фото → настройка → генерация
```

Маршрут `/app` не показывает самостоятельную страницу. Он только находит или
создаёт пустой проект и перенаправляет пользователя на `/app/[id]`.

## 2. Новая карта страниц

- `/app` — защищённая серверная точка входа в редактор без собственного UI.
- `/app/[id]` — единственная страница проекта: загрузка исходника, разметка,
  референсы, prompt, стиль, модель, генерация и результаты.
- `/app/history` — история генераций.
- `/app/profile` — профиль пользователя.
- `/admin` — административная панель.
- `/app/design` — совместимый redirect на `/app`.
- `/app/design/[id]` — совместимый redirect на `/app/[id]`.

Статические сегменты `history` и `profile` имеют приоритет над динамическим
`[id]` в Next.js 16, поэтому они не интерпретируются как идентификаторы проекта.

## 3. Поведение `/app`

После проверки сессии сервер вызывает один owner-scoped сервис:

```ts
getOrCreateEntryProject(userId: string)
```

Сервис ищет самый новый незаполненный проект пользователя со следующими
признаками:

- `status = DRAFT`;
- `deletedAt = null`;
- `sourceImageId = null`;
- `sourcePreviewId = null`.

Если такой проект найден, он используется повторно. Иначе создаётся проект с
названием `Новый интерьер`. Затем `/app` выполняет server redirect на
`/app/${project.id}`.

Такой подход не создаёт новый пустой проект при каждом входе или повторном
нажатии «Новый дизайн». Бизнес-данные по-прежнему читаются и изменяются только
через Prisma.

## 4. Единый workspace

`/app/[id]` загружает принадлежащий пользователю проект независимо от наличия
исходной фотографии.

### Проект без фотографии

Пользователь видит обычную шапку workspace и тёмный холст. На месте карточки
исходника находится крупная зона загрузки:

- выбор файла по нажатию;
- drag-and-drop;
- локальный preview выбранного изображения;
- требования JPG, PNG или WEBP, до 15 МБ, минимум 512 × 512 px;
- состояние загрузки и понятная ошибка;
- действие замены выбранного файла до отправки.

Правая AI-панель остаётся видимой, чтобы пользователь сразу понимал дальнейший
процесс, но генерация, разметка и управление референсами недоступны до успешной
загрузки. Причина блокировки отображается текстом `Сначала загрузите фотографию
помещения`.

Загрузка отправляет файл напрямую в существующий endpoint:

```text
POST /api/v1/projects/[id]/source
```

Компонент больше не создаёт второй проект через `POST /api/v1/projects`.
Название пустого проекта обновляется из имени файла только если оно всё ещё
равно `Новый интерьер`. После успеха вызывается `router.refresh()`, URL не
меняется, и пустое состояние заменяется полноценным холстом.

### Проект с фотографией

Существующие возможности workspace сохраняются без изменений:

- pan/zoom;
- Fabric-разметка;
- undo/redo;
- референсы;
- prompt и стили;
- модель и формат;
- генерация, polling и результаты на холсте;
- просмотр до/после и скачивание.

Signed URLs создаются только для реально существующих source preview и
референсов.

## 5. Навигация

В шапке workspace ссылка на удалённый список проектов заменяется действием
`Новый дизайн`, ведущим на `/app`. Рядом остаются `История` и `Профиль`.

На страницах истории, профиля и админки ссылки `Рабочая область`,
`Новый дизайн` или `В приложение` ведут на `/app`. Поскольку `/app` является
redirect-точкой, пользователь сразу возвращается в пустой редактор.

OAuth callback сохраняет `/app` как безопасный маршрут по умолчанию. Явный
параметр `next` продолжает поддерживаться для `/admin` и защищённых deep links.

## 6. Совместимость и ошибки

- Существующие закладки `/app/design/[id]` получают permanent redirect на
  `/app/[id]`.
- `/app/design` перенаправляет на `/app`.
- Неизвестный или чужой project ID на `/app/[id]` возвращает `notFound()`.
- Неавторизованный пользователь перенаправляется на `/login`.
- Ошибки проверки или загрузки изображения показываются внутри upload-карточки;
  пользователь остаётся на том же project URL и может повторить попытку.
- База данных и Prisma schema не меняются.

## 7. Границы компонентов

- `getOrCreateEntryProject` отвечает только за выбор или создание пустого
  owner-scoped проекта.
- `/app/page.tsx` отвечает только за auth и redirect.
- `/app/[id]/page.tsx` отвечает за server-side загрузку проекта и signed URLs.
- `DesignWorkspace` координирует два состояния одного интерфейса: `empty-source`
  и `ready`.
- `SourceUpload` принимает существующий `projectId` и отвечает только за выбор,
  preview и загрузку файла.
- `WorkspaceHeader` отвечает за навигацию и редактирование названия.

## 8. Проверка

Проект сохраняет текущую договорённость не добавлять отдельный автоматизированный
test harness. Изменение проверяется существующими командами:

```bash
pnpm typecheck
pnpm lint
pnpm build
```

После статических проверок `agent-browser` проверяет:

1. `/app` перенаправляет авторизованного пользователя на `/app/[id]`.
2. Новый проект показывает upload-состояние внутри workspace.
3. `/app/history` и `/app/profile` открывают статические страницы, а не `[id]`.
4. Успешная загрузка оставляет пользователя на том же `/app/[id]`.
5. После refresh отображается полноценный canvas и доступна AI-панель.
6. Старые `/app/design` и `/app/design/[id]` корректно перенаправляются.
