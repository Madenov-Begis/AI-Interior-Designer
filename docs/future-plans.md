# Ruvie — дальнейшие планы развития

- Статус: отложено до запуска текущей версии
- Источник идей: анализ аналогичных сервисов интерьерной визуализации
- Текущий приоритет: выпустить Ruvie с уже реализованными функциями

## 1. Контекст

Aidentika не следует копировать целиком. Для Ruvie полезны продуктовые механики, которые превращают разовую AI-генерацию в последовательный процесс интерьерного проектирования.

До запуска текущей версии перечисленные ниже функции не входят в обязательный scope, не должны задерживать релиз и требуют отдельного планирования после запуска.

## 2. Что уже реализовано в Ruvie

Повторная разработка этих возможностей не требуется:

- Google OAuth;
- проекты, поиск и каталог;
- загрузка референсов;
- визуальная разметка помещения;
- дерево версий и доработки от выбранного результата;
- кредиты и история операций;
- автоматический возврат кредитов при технической ошибке;
- интерьерные стили;
- выбор формата изображения;
- скачивание готового результата.

## 3. Планируемые возможности

### P0 — основной следующий этап после запуска

#### 3.1. Замена объекта или материала

Адаптация функции «Замена товара» из Aidentika для интерьера.

Пользователь должен иметь возможность:

1. Открыть готовый результат.
2. Выделить диван, стол, шкаф, стену, пол или другую область с помощью существующей визуальной разметки.
3. Добавить фотографию нового предмета или материала как референс.
4. Выбрать режим замены.
5. Получить дочернюю версию без изменения остального помещения.

Режимы:

- **Точная замена** — максимально точно воспроизвести предмет с референса.
- **Адаптировать** — сохранить характер предмета, но изменить ракурс, свет и пропорции для естественного размещения.
- **Вдохновиться** — использовать визуальную идею референса, не копируя его буквально.

Для реализации можно использовать существующие механизмы visual prompting, refinement, generation references и `parentGenerationId`.

#### 3.2. ДНК интерьера

Постоянный дизайн-профиль проекта или объекта, который обеспечивает единый стиль между версиями и комнатами.

Профиль может хранить:

- цветовую палитру;
- основные материалы;
- тип и температуру освещения;
- язык и формы мебели;
- декоративные акценты;
- элементы, которые необходимо сохранить;
- запрещённые изменения;
- набор основных референсов;
- дополнительные текстовые правила.

ДНК интерьера должна автоматически добавляться в последующие генерации выбранного проекта и при необходимости применяться к другим комнатам объекта.

#### 3.3. AI-идея

Помощник, который анализирует загруженное помещение и предлагает готовые направления редизайна.

Возможный результат анализа:

- тип помещения;
- существующий стиль;
- освещение;
- основные материалы;
- визуальные проблемы;
- элементы, которые желательно сохранить;
- три варианта изменений с готовыми промптами.

Пользователь сможет выбрать предложение, отредактировать его и запустить обычную генерацию.

#### 3.4. Центр действий после результата

Окно просмотра результата должно стать точкой продолжения сценария.

Планируемые действия:

- доработать результат;
- заменить объект или материал;
- создать альтернативный вариант;
- применить стиль к другой комнате;
- сравнить с исходной фотографией;
- скачать изображение.

#### 3.5. Сравнение «до/после»

Добавить отдельный интерактивный режим сравнения исходной фотографии и выбранной генерации:

- разделитель-слайдер;
- переключение «до/после»;
- полноэкранный просмотр;
- возможность скачать отдельные изображения.

### P1 — развитие проектного процесса

#### 3.6. Объект с несколькими комнатами

Добавить сущность верхнего уровня — квартира, дом, офис или клиентский объект.

Пример структуры:

```text
Квартира
├── Общая ДНК интерьера
├── Гостиная — утверждена
├── Кухня — дорабатывается
├── Спальня — три варианта
└── Ванная — исходник ещё не загружен
```

Каждая комната может остаться обычным проектом Ruvie. Объект объединяет проекты, общую стилистику и прогресс.

Отдельный сложный графовый редактор для этого не требуется. Достаточно списка комнат, статусов и общего дизайн-профиля.

#### 3.7. Расширенная библиотека проектов

Планируемые метаданные и инструменты:

- папки или объекты;
- имя клиента;
- тип помещения;
- статус проекта;
- теги;
- избранное;
- фильтрация и сортировка;
- архив завершённых проектов.

### P2 — функции для профессиональных пользователей

#### 3.8. Команды и общий баланс

Для дизайнеров и студий:

- приглашение участников;
- роли и права доступа;
- совместные проекты;
- комментарии или согласование;
- общий либо раздельный кредитный баланс;
- история действий участников.

Разрабатывать после подтверждения спроса со стороны дизайн-студий.

### P3 — интеграции

#### 3.9. Public API и webhooks

Возможные клиенты:

- застройщики;
- мебельные магазины;
- агентства недвижимости;
- ремонтные компании;
- интерьерные CRM и каталоги.

Предполагаемая схема:

1. Создание асинхронной генерации.
2. Получение идентификатора задачи.
3. Проверка статуса или webhook.
4. Получение результата.
5. Идемпотентность запросов и списаний.

API следует разрабатывать только после появления подтверждённого B2B-сценария.

## 4. Что пока не планируется

- Генерация видео как часть основного продукта.
- Большое количество способов авторизации до появления необходимости.
- Реферальная программа до подтверждения удержания пользователей.
- Выбор конкретной AI-модели пользователем.
- Короткий срок хранения интерьерных проектов.
- Командные тарифы до появления первых студийных клиентов.
- Публичный API без подтверждённого спроса.

## 5. Предварительная последовательность после запуска

1. Центр действий после результата.
2. Сравнение «до/после».
3. AI-идея.
4. Замена объекта или материала.
5. ДНК интерьера.
6. Объекты с несколькими комнатами.
7. Расширенная библиотека проектов.
8. Команды и общий баланс.
9. Public API и интеграции.

## 6. Условие начала работ

Работа над этим roadmap начинается только после запуска и стабилизации текущей версии Ruvie. До этого момента приоритет имеют:

- production-конфигурация;
- реальные платежи;
- проверка полного пользовательского пути;
- стабильность генерации;
- безопасность и хранение данных;
- мониторинг ошибок;
- выпуск текущего набора функций.
