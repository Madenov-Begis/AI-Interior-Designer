# Fullstack-функция Ruvie

Используй этот workflow для законченного вертикального изменения. Для локальной правки текста, одного стиля или независимого helper этот skill не нужен.

## Контекст

1. Прочитай применимые `AGENTS.md`.
2. Найди соответствующий сценарий в `docs/full-product-documentation.md`.
3. Если меняются зависимости слоёв или данные, прочитай `docs/architecture.md` и `prisma/schema.prisma`.
4. Изучи текущие route, UI, service/operation, типы и тесты. Не проектируй параллельную реализацию до понимания существующей.

## Проектирование

Перед кодом зафиксируй:

- наблюдаемый результат для пользователя или администратора;
- затронутые роли и ownership;
- входные данные и validation;
- loading, empty, error, retry, disabled и success состояния;
- бизнес-инварианты и идемпотентность;
- изменения API/DTO/Prisma;
- минимальный набор тестов;
- необходимость обновить документацию.

Для неоднозначного решения предложи короткий план. Не проси подтверждение для обычных локальных implementation-решений, если они не меняют согласованный scope.

## Реализация

- Сохраняй `src/app` тонким.
- Размещай пользовательский UI в `src/client`, бизнес-логику в `src/server`, административный UI в `admin/src`.
- Используй существующие компоненты, API-клиенты, schemas, services и policies.
- Доверяй ownership, статусам и финансовым данным только после server-side проверки.
- Для финансовых и generation-операций сохраняй транзакционность и idempotency.
- При изменении Prisma создавай новую migration.
- Не изменяй несвязанные пользовательские файлы и не выполняй deploy/commit без запроса.

## Проверка

Выбери проверки по `docs/testing.md`.

Минимально:

- релевантные unit/UI/integration tests;
- typecheck затронутого приложения;
- lint при изменении исходного кода;
- build при изменении маршрутов, конфигурации или сборочных границ;
- browser verification для значимого UI.

Перед завершением просмотри diff на утечку secrets, обход ownership, рассинхронизацию frontend/backend validation, двойное финансовое действие и устаревшую документацию.

## Результат

Сообщи:

- что изменилось для пользователя;
- какие слои и файлы затронуты;
- какие проверки реально прошли;
- что не проверено и почему;
- остались ли риски или внешние шаги.
